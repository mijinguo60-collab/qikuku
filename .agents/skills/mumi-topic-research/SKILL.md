# Mumi 选题调研

输入一个选题。目标不是堆链接，而是判断普通人现在是否真的有这个问题、能否用大陆直连工具实测出步骤、是否值得做成教程。

## 流程

1. 把选题改写成一个可验证的任务句：谁，在什么场景，用什么工具，想得到什么结果。
2. 搜索近 30–90 天的搜索结果、平台公开内容、官方文档、产品更新和用户讨论。区分“有人讨论”与“有人解决”。
3. 提取 3–5 个真实痛点：原始问题、失败原因、现有内容缺口、用户愿意复制的动作。
4. 检查工具是否在允许清单内，能否大陆直连，是否有免费或低成本路径；不能确认的写“待实测”。
5. 找 3–8 条相近内容作竞品扫描，只记录公开可核验的标题、发布时间、内容角度和缺口；不抄标题，不把点赞量当成转化证明。
6. 给出 GO / 收窄 / 暂缓判断，并列出下一步最小实测：输入材料、操作步骤、成功判据和失败记录。

## 产出格式

```markdown
# 选题调研：<题目>
调研日期：YYYY-MM-DD
判断：GO / 收窄 / 暂缓

## 一句话任务
## 目标读者与具体痛点
## 热度信号（来源、日期、观察范围）
## 现有内容与缺口
## 工具实测计划
## 可能失败与合规风险
## 内容角度与标题方向
## 下一步最小实测
## 引用来源
```

每个外部事实紧跟链接和访问日期。热度不足时不硬凑“爆款”；公开页面不可访问时保留原始错误并换可靠来源。
