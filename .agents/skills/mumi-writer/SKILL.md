# Mumi 写作

## 写作内核

从具体失败或结果开头，让读者马上知道这篇能帮他完成什么。正文围绕“任务—准备—操作—结果—原理—失败点—复制材料—下一步”推进。每一步写真实动作和判断依据，不能只说“输入提示词即可”。

语气直接、短句为主、说人话。允许承认失败和限制，不套用任何其他作者的口头禅、脏话或人物口吻。避免“首先/其次/最后”“综上所述”“值得注意的是”“让我们来看看”“在当今时代”等通知式套话。

## 硬约束

- 只写已实测或明确标注为待实测的中国大陆直连工具；可用工具名以总管线清单为准。
- 标题痛点前置、工具后置；优先使用“数字 + 人群 + 痛点 + 结果”组合，但不虚构结果数据。
- 至少提供一个可复制的提示词、模板、表格或检查清单原文。
- 说明为什么这样做、哪里容易失败、人工要检查什么。
- 不承诺爆单、暴富、固定收入或必然效果；结尾只引导收藏、评论、补充实测问题。
- 文末加 AI 辅助创作标识文案。

## 四个平台

### 小红书

给 3 个标题候选，正文短段落，开头直接给结果，步骤用可收藏的编号，重点放提示词和避坑；话题不超过 8 个且与内容相关。

### 抖音

给标题、30–90 秒口播稿、镜头/录屏动作和话题。每 3–8 秒有一次画面变化，企鹅可以作为讲解 IP 出镜；长步骤切成“看到问题—操作—结果—限制”四段。

### 公众号

给完整 Markdown 长文，不照搬小红书。加入实测环境、操作理由、失败记录、适用边界和搜索友好小标题，正文保留可复制代码块或提示词。

### 小绿书

给短标题、短正文、步骤卡文案和评论区可继续追问的问题，内容可以复用小红书的实测结论，但不要机械复制排版。

## 交稿自查

在交给 `mumi-copy-review` 前，逐项检查：具体工具名、真实动作、结果证据、限制、可复制材料、收藏/评论钩子、AI 标识、无翻墙工具名、无收益承诺。
